# Final engineering recommendation

Labels: **[T]** theorem (proved from public sources or in-session math), **[A]** assumption, **[P]** empirical prediction, **[S]** speculation.

## 1. The one submission design (module / state-shape level)

**[A-design]** Everything below is load-bearing; anything not listed was deleted.

| Module | Shape / spec | Why it survives the cut |
|---|---|---|
| Token embedding | `17 × 256`, fixed sinusoidal positions | input only |
| Prompt memory | prompt tokens embedded once per forward, projected to d=256; register cross-attends to it every step | \(N\) must be visible at every step (cross-\(N\) function, not memorized \(N\)) |
| Loop state \(S\) | canonical register: \(L\) decimal slots × 10-way one-hot, \(L\) = max \(N\)-field digit length in batch | minimal sufficient loop state; bottleneck blocks smuggled encodings (H2) |
| Cell \(G_\theta\) (tied, homogeneous) | 2 pre-LN blocks, d=256, 4 heads: self-attn over \(L\) slots + cross-attn to prompt memory + MLP(×4). ≈2.3M params total | capacity starvation is the only legal depth-prior and Occam instrument (§2) |
| Anchor | per step, one extra cell application at constant register ONE; \(\widehat G = G(S,n) - G(\iota 1,n) + \iota 1\) in pre-quantizer space | kills ambiguity family (a), §2 |
| Quantizer | per-slot argmax, straight-through, **hard from step 0** | no train/eval gap; re-canonicalization makes exactness inductive |
| Loop control | decode integer \(T\) from the T-field digit tokens; apply cell \(T\) times; read final register | forces compositional roots, not loop-count roots (§2); legality risk §5 |
| Readout | per-slot logits at final step, right-aligned to target length; return `(logits, None)` | state already *is* the answer digits |

Deleted: halter, output selection, learned or fixed step codes, scratchpad/memory tokens, consistency losses, auxiliary heads, multi-pass callbacks. **[P]** 2 layers × 64 steps ≈ 128 layer-passes on ≤100 tokens — milliseconds per 10³-example batch; the 1,800 s eval budget is not a constraint.

## 2. The three ambiguity families, confronted

Setup **[T, from source]**: if Hard mirrors Medium, training depths are all even and \(\min D \ge 2\) (M1/M2: {4,8,16}; M3: {2}; M4: {8}; M5: {2,4,8}).

**(a) Scalar gauge \(G_c(u) = c u^2\), \(c^g = 1\), \(g = \gcd(2^{T_i}{-}1)\).** **[T]** Fits every training label exactly; 14 nontrivial instances exist at M1's actual \(N = 101 \cdot 103\). **Excluded by the anchor [T]**: family (a) has \(G_c(1) = c\); the anchor architecturally enforces \(\widehat G(1, n) = \iota(1)\) for every \(n\), so the hypothesis class contains only \(c = 1\). This is exclusion by parameterization, not by data, and it is exact.

**(b) Inverse squaring \(G(u) = u^{-2}\).** **[T]** \(G^{\circ T} = f^{\circ T}\) for all even \(T\), so it fits *every* label of *every* Medium tier and certifies all even ladder rungs while scoring 0 at \(T = 1\). The anchor does **not** exclude it (\(u^{-2}\) fixes 1). No exclusion theorem is available: \(u^{-2}\) is exactly representable in the digit-register class (inversion is a polynomial-size circuit), so finite-sample agreement proves nothing — I am not claiming polynomial identity. The only discriminator is asymmetric circuit complexity: exact modular inversion needs a much deeper circuit than squaring, and a 2-layer starved cell plausibly cannot implement it in one application, while it can implement multiply-reduce. **Verdict: an Occam bet [A], not a theorem.** It becomes data-excluded **[T]** iff Hard's training set contains any odd depth.

**(c) Permutation/coboundary roots.** **[T, construction on cycles]** On an \(f\)-cycle of length \(k\), set \(G(u_i) = a_{i+1} a_i^{-2} u_{i+1}\) with \(a_i \in \mu_g\) constant on cosets of the shift subgroup generated by \(D\) in \(\mathbb Z_k\); then \(G^{\circ T_i} = f^{\circ T_i}\) for all training depths, and the gauge is non-scalar whenever \(\gcd(T_i \text{'s}, k) > 1\) — guaranteed for all-even \(D\) on even-length cycles. The anchor does not exclude it (choose \(a = 1\) at the fixed point 1). **Verdict: not excludable; also an Occam bet [A]**, but a stronger one: representing an \(N\)-dependent family of arbitrary permutations is high-complexity, and sampled-\(N\) training (M3/M5-style, likely Hard) forces the same parameters to implement it per-modulus — compressibility collapses. Fixed-\(N\) training is the worst case for all three families.

**Net [T + A]:** with all-even training depths, (a) is architecturally excluded, (b) and (c) are not; recovery of the true one-step map is *impossible to guarantee* and rests on the Occam bet that the minimal-capacity exact solution of the composed constraints is \(u \mapsto u^2\). With any odd training depth, (b) dies by data; with \(T = 1\) present, (a),(b) die and (c) shrinks to off-support freedom (irrelevant under E1/E2-style exhaustive-x eval). **Everything hinges on a property of Hard's hidden training set we cannot observe (§7).**

## 3. Six-experiment remote-GPU ladder (H100 rental, official CLI, public tiers)

Primary metrics everywhere: **T=1 seen-N exact-match** and **T=1 OOD-N exact-match** (per-rung tables at 1,2,4,…,64). Artifacts per run: `metrics.jsonl` (loss + per-rung accuracy vs step), rung table, drift probe (per-step readout accuracy on held-out units), checkpoint, config + manifest hash. Evaluator-owned seeds; 3 runs where stated.

## 4. Training schedule and loss (legal inputs only: `batch.logits, batch.labels, batch.valid_mask`)

**[A-design]** AdamW, lr 2e-3, β=(0.9, 0.95), weight decay 0.1 on matrices only (none on embeddings/norms), warmup 1% of steps then cosine to 0. Batch 512 train / 1024 eval. `max_steps` calibrated so training ends at ≈85% of the 3,600 s wall clock (measured from E-tier runs). Loss = `token_training_loss`: per-example mean CE over valid target tokens, batch mean, full stop. No label smoothing (exactness), no intermediate-state terms, no consistency terms, `backward_passes_per_step = 1`, batch reuse off. Levers held in reserve if wall-clock is underused (multi-pass) or a rung stalls at 99.x% (max-over-positions emphasis term) — each is a one-experiment change, not in the first file.

## 5. Strongest legality risk

Decoding the prompt's T-field digits to an integer and using it as the loop bound (§1) is base-10 decoding outside the autograd graph; a strict reading of Rule 7 ("no hard-coded algorithm in the forward pass") could class it as non-learned arithmetic on inputs, even though Rule 3 explicitly allows adaptive computation and the loop count carries no gradient in *any* adaptive-computation scheme. (The anchor is the second risk; it stores no weights and computes no task arithmetic — a one-point reparameterization.)

**Exact organizer question:** *"May `forward` decode the integer value of the prompt's T field from its digit tokens and use it as the iteration count of a weight-tied learned recurrence, with all residue arithmetic performed by learned modules?"*

If the answer is no, fallback (strictly worse, §2): fixed 64-step unroll with learned content-based selection — which reopens loop-count-root evasions.

## 6. First submitted file

**In:** §1 design at the E5-validated capacity; §4 schedule and plain CE; anchor on; T-parse loop; homogeneous cell; batch 512/1024; `max_steps` at 85% of budget. **Out:** halter/selection machinery, Fourier t-code (added only if the first run proves the recurrence is non-homogeneous), all auxiliary losses, multi-pass/reuse callbacks, focal terms, scratchpad.

**Expected failure mode [P]:** OOD-N T=1 exact-match < 100% ⇒ OOD-N Max T = 0; ranking then rides on ID Max T and the first-uncertified-rung tie-breaker. Secondary [P]: if Hard trains on all-even depths and the Occam bet loses, ID T=1 ≈ 0% (the \(u^{-2}\) signature is unambiguous: even rungs certify, rung 1 is zero) — that outcome is a one-line diagnostic, not a mystery.

## 7. The question this roundtable never asked

**Is the Hard ladder winnable as scored — does h1's training set contain an odd depth (ideally T=1)?** If yes, one-step identifiability is data-driven and the design's only real exposure is A2. If no, certification past rung 0 is prior-luck for *every* team by Theorem 2's invariance, the benchmark's certification ranking is noise, and the true optimization target is the tie-breaker — accuracy at the first uncertified rung — which would change the loss (max-emphasis becomes primary, capacity starvation gets relaxed). No amount of architecture work substitutes for this bit of information, and the only legal instrument that reveals it is the one-attempt-per-day submission itself: the first file doubles as a distribution probe, and its rung-profile result answers §7 before any second submission is designed.
